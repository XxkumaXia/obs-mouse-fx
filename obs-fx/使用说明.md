# OBS 鼠标高亮叠加（滤镜版）

一个 OBS **内置 Lua 脚本**，装上以后会在画面上直接画出：

- 常驻的**高亮圈**：外环 + 内部圆形填充可分别开关（默认黄环 + 半透明黄填充）
- **点击时的扩散波纹**（左/右/中键可分别设颜色，支持多重环）
- 可选的**移动拖影**
- **自绘光标**：自动读取你 Windows 当前的鼠标指针，画在高亮圈**之上**，
  所以高亮圈永远在光标「下面」，不会把光标染色 / 盖住（换光标主题也会自动跟上）

坐标由脚本通过 Win32 API 实时读取，**不需要** Python 服务、不需要浏览器源、不需要开任何后台程序。

> 这是唯一版本（早期的 Python 服务 + 浏览器源那套已删除）。

---

## 一、装一次就行

1. OBS 菜单 → **工具 → 脚本**
2. 点 **+** → 选 `obs-fx\mouse-fx.lua`
3. 脚本面板下方就是全部参数，改完**立即生效**

`mouse-fx.effect` 和 `blank.png` 必须和 `mouse-fx.lua` 放一起，不要拆开。

> 提示：OBS 脚本路径最好不要包含中文（个别版本加载非 ASCII 路径会失败），
> 不放心可以把整个 `obs-fx` 目录拷到纯英文路径（如 `D:\obs-fx`）再加载。

## 二、两种用法

### 用法 A：给采集源加滤镜（推荐）

来源（显示器采集 / 窗口采集）右键 → **滤镜** → 左下 **+** → 选 **鼠标高亮叠加 (Mouse FX)**。

- 滤镜会**自动识别你采集的是哪块屏幕**并换算坐标（多屏也不用管，日志里会打印匹配结果）
- 光标由脚本自己画（见下面「光标压在上层」一节），不需要你再动采集源的「捕获光标」

### 用法 B：独立叠加层

场景 → 来源 **+** → **鼠标高亮层 (Mouse FX)**，拖到最上层。

> 独立层是**独立图层**，没有「挂在哪个采集源下面」。但只要填好下面的
> **联动缩放源**（或「接管用的采集源名」），脚本就能按名字找到那台采集源、
> 读出它正在捕获哪块屏——**区域和宽高都自动跟随，换屏录制不用改任何设置**：

1. 「坐标区域」选 **自动**，「联动缩放源」选你正在录的那块屏的采集源（如 `显示器采集`）
2. 完事。日志会出现 `独立源自动匹配：联动源「显示器采集」捕获 309,-1080 1920x1080`
   和 `独立源宽高已跟随捕获的显示器：1920x1080`
3. 采集源属性里把显示器换成另一块屏，**2 秒内**区域和宽高自动跟着换（多屏兼容）
4. 也可以手动固定：「坐标区域」选 **指定显示器**，下拉里挑屏（选项带坐标，
   例如 `DELL U2417H [309,-1080 1920x1080]`），再把「独立源 宽/高」设成该屏分辨率

读不到采集源时（源被删 / 不是显示器采集 / 显示器识别失败），脚本连续重试约 6 秒后
打一条 INFO 提示，并退回「指定显示器」→ 主屏，不会瞎定位（提示只在勾了「输出日志」
时可见；默认完全安静，只有 effect / 贴图加载失败才会弹日志窗）。

### 配合 obs-zoom-to-mouse 缩放跟焦（联用注意事项）

两个脚本叠加用没问题，但下面几条是**硬规则**，违反就会出现「两个圈」「一大一小」
「颜色发灰」「两个光标」这类灵异现象。每条都是真机踩出来的。

**① 两种用法二选一，绝不能同时开**

- 用法 A：采集源上挂「鼠标高亮叠加」滤镜 → 场景里就**不要**再放「鼠标高亮层」
- 用法 B：场景里放「鼠标高亮层」→ **它身上不要再挂任何滤镜**
- 典型事故：给「鼠标高亮层」又挂了个「鼠标高亮叠加」滤镜——同一个效果画了两遍：
  底层（独立源本体）跟着 zoom 放大重映射，顶层（那个滤镜）不参与重映射、停在原始
  坐标和原始大小，于是一大一小、位置分家；半透明柔光两遍叠加深色，颜色还发灰。
  **独立源是最终输出层，挂任何滤镜都是画两遍。** 中招了就进「鼠标高亮层」的滤镜
  面板把「鼠标高亮叠加」删掉（不是取消勾选，是删掉）。

**② 滤镜版必须挂在采集源上，并排在 zoom 裁剪滤镜下方**

zoom 脚本的放大原理是「裁剪滤镜把画面压小 + 场景项拉伸回原尺寸」。「鼠标高亮叠加」
排在裁剪滤镜**下方**时画的是全尺寸画面，会跟着一起被裁剪放大，天然对齐。
顺序不用手动管——zoom 脚本会周期性把裁剪滤镜推到滤镜链最上方（最终输出），
防止被高亮滤镜挤掉导致放大失效。

**③ 独立源版：拖到场景最上层，填好「联动缩放源」**

1. 选中被 obs-zoom-to-mouse 缩放的那台**采集源**（如 `显示器采集 2`）
2. 高亮层每帧读取它身上那枚裁剪滤镜（固定名 `obs-zoom-to-mouse-crop`）的当前裁剪框，
   把光标坐标按「减裁剪框 → 乘拉伸倍率」重映射，**高亮圈和柔光尺寸也同步乘上放大倍率**
3. 放大、跟随鼠标、缩回，全程自动对齐，不需要再动「缩放修正」
4. 只认精确名 `obs-zoom-to-mouse-crop`：你自挂的 Crop/Pad、zoom 脚本把场景项 transform
   裁剪转成的 `temp_obs-zoom-to-mouse-crop` 临时滤镜，都不会被误当裁剪框
5. 联动源被改名后 2 秒内自动重找；新建的源不出现在下拉里就重新加载一次脚本

**④ 采集源的「捕获光标」保持关闭**

两个脚本都不碰这个开关。mouse-fx 的「自绘接管」会自动关掉它，改由脚本把当前系统
光标画在最上层（圈永远在光标下面）。谁手动勾回来，谁就是两个光标。

**⑤ 多屏 / 换屏录制**

「坐标区域」选**自动** + 「联动缩放源」填当前在录那块屏的采集源：区域和宽高自动
跟随，采集源属性里换块屏 2 秒内跟上，两个脚本不用任何改动。
**不要选「主屏」**——Windows 的「主显示器」名分不一定在你录的那块屏上
（名分在 SKG27B2、录的是 AOC2477 这种错位，一放大光标和圈必飞）。

**⑥ 滤镜懒建，等一下就好**

zoom 脚本加载 / 切场景后，裁剪滤镜要几秒才出现。mouse-fx 找不到时按未放大处理，
连续约 6 秒后才打一次警告；滤镜建好后自动接上，不用管。

## 二点五、让高亮圈「在光标下面」

**为什么需要这一步**：OBS 的「显示器采集」在勾了「捕获光标」时，会把系统光标
**直接画进采集画面里**。而高亮圈是叠在这张画面之上的图层——物理上不可能钻进画面内部，
所以只要填充是半透明的，光标就会被染成黄色、看起来「被盖住」。

**本插件的做法**：关掉采集源的「捕获光标」，改由脚本**把当前光标自己画一遍**，
并且画在最上层。于是图层顺序变成：

```
拖影 → 柔光 → 波纹 → 填充 → 外环 → 光标      ← 光标永远在最上面
```

**怎么用**（默认已开，开箱即用）：

1. 「自绘光标（永远画在高亮圈之上）」保持勾选
2. 「自动读取系统当前光标」保持勾选 —— 脚本每次渲染时直接向 Windows 要当前光标的位图
   （含热点），所以：
   - 你**换光标主题 / 换形状**（箭头↔文本↔手型↔忙碌）→ 自动跟上，不用改设置
   - 动画光标（`.ani`）→ 启动时连采 5 帧，按「多帧光标帧率」循环播放
3. 「自绘接管」保持勾选 —— 它会**自动帮你关掉**采集源的「捕获光标」（取消勾选会自动恢复）
4. 万一换了主题没自动跟上（Windows 偶尔会把**同一个光标句柄**回收给新光标，
   脚本光看句柄就分辨不出来），点一下 **「重新抓取光标」** 按钮即可强制重取；
   换过 `cursor.png` 图片、想让它重新读盘也点这个按钮

**自动读取失败时**（极少见，勾「输出日志」会有提示）才会退回下面这两层兜底：

- 「光标图片」：默认 `cursor.png`（本插件自带的中性箭头图，32×32 单帧，热点 1,1，
  由 `dev-archive/make_cursor_png.py` 生成）。想换成别的图片就填路径（相对脚本目录），
  多帧图按「图片帧数」横向平铺，单帧图保持 1 即可，热点填该图的作用点坐标
- 都失败 → 画内置箭头（填充色 / 描边色可调）

> 自动读取失败不会一直卡住：脚本每 2 秒重试一轮，期间由「光标图片 / 内置箭头」
> 顶着画面，一旦能取到就自动切回真光标。

## 三、参数

脚本面板里分组如下：

| 组 | 关键项 | 说明 |
|---|---|---|
| 坐标区域 | 自动 / 主屏 / 虚拟桌面 / 自定义 / **指定显示器** | **自动**：滤镜读挂载目标那块屏；独立层读「联动缩放源」捕获的显示器（区域+宽高都跟随） |
| 坐标区域 | **指定显示器（下拉）** | 列出本机所有屏（带屏名+坐标），挑你录的那块；「自动」读不到联动源时也用它兜底 |
| 坐标区域 | 整体偏移 X/Y、缩放修正 | 有偏差时微调；缩放修正是给画面被裁剪/缩放的情况 |
| 坐标区域 | **联动缩放源** | 配合 obs-zoom-to-mouse：独立层按被缩放采集源的裁剪框重映射坐标，放大也对齐 |
| 常驻高亮圈 | **高亮样式** | 外环+内部填充（默认）/ 仅外环 / 仅内部填充 |
| 常驻高亮圈 | 半径 / 外环粗细 / 颜色 | 默认 半径 32、粗细 4、黄 `#FFD400` |
| 常驻高亮圈 | 外环不透明度 / 内部填充强度 | 默认 0.9 / 0.38 |
| 常驻高亮圈 | 圆心下移 | 让填充圆和柔光整体下移。**现在不需要了**（光标改由脚本画在上层），保持 0 即可 |
| 常驻高亮圈 | 柔光开关 / 半径 / 强度 | 柔光也跟着「圆心下移」一起动 |
| 点击波纹 | 单环持续、起始/结束半径、环粗细 | 扩散效果 |
| 点击波纹 | 重数 1~3、重间延迟 | 2 = 双环 |
| 点击波纹 | 左/右/中键颜色、内部填充强度 | 默认黄 / 红 / 绿 |
| 移动拖影 | 残影数量、半径、采样间隔、颜色 | 默认关闭 |
| **自绘光标** | **启用自绘光标** | 默认开。关掉的话要用采集源的「捕获光标」，高亮圈又会盖住光标 |
| **自绘光标** | **自动读取系统当前光标** | 默认开。运行时直接从 Windows 取光标位图，换主题 / 换形状自动跟上 |
| **自绘光标** | **重新抓取光标**（按钮） | 换了主题 / 图片没自动跟上时点一下，强制清空重取（换 `cursor.png` 后也点它重新读盘） |
| **自绘光标** | 光标图片 / 图片帧数 / 帧率 / 热点 X,Y | 只在自动读取关掉或失败时用；自带 `cursor.png` 是 32×32 单帧、热点 1,1 |
| **自绘光标** | 光标缩放 | 默认 1.0（1:1 还原系统光标大小） |
| **自绘光标** | **自绘接管** | 默认开。自动关掉采集源的「捕获光标」（画面上两个光标的根因） |
| **自绘光标** | 接管用的采集源名 | 独立源必填；留空 = 用「联动缩放源」那个（一般就是「显示器采集」） |
| 自绘光标 | 箭头填充色 / 描边色 | 自动读取和图片都失败时的兜底 |
| 其它 | 跟手程度 | 1 = 完全不插值，最小延迟；调小会变"拖沓"一点点 |
| 其它 | 独立源 宽/高 | 只影响用法 B；「自动」模式下自动跟随捕获的显示器，探测不到才用手动值 |
| 其它 | **输出日志（调试用）** | 默认**关闭**。关闭时脚本一条日志都不打、也绝不弹窗（OBS 只对 WARNING 以上级别的脚本日志弹窗，本脚本这类提示全是 INFO）；排障时再打开。同一提示 60 秒内只打一次，反复删加源也不会刷 |

## 四、图层顺序（谁压住谁）

从下到上固定为：

```
拖影 → 柔光 → 点击波纹 → 内部填充 → 外环 → 箭头光标
```

- **默认走「自绘光标」**：脚本关掉采集源的「捕获光标」，再把当前系统光标画在最上层，
  所以高亮圈永远在光标下面（这才是「圈在光标底下」的效果）
- 关掉「自绘光标」才会用采集源自带的系统光标。那时系统光标**被烤进采集画面里**，
  高亮圈一定叠在它上面 → 柔光/填充开太大就会蒙在光标上
- 「颜色」选出来的颜色不对（红变蓝等）说明脚本版本旧，本版已修复（OBS 颜色字节序是低字节为 R）

## 五、排障

脚本运行时会在 OBS 日志里留几行（**帮助 → 日志文件 → 显示现有日志文件**）：

```
[鼠标高亮] 已加载。区域 0,0 2560x1440
[鼠标高亮] 画面尺寸 1920x1080，映射区域 309,-1080 1920x1080
[鼠标高亮] 自动匹配采集显示器：309,-1080 1920x1080
[鼠标高亮] 首帧渲染完成（1920x1080）
```

| 现象 | 处理 |
|---|---|
| 脚本面板里看不到参数 / 加载报错 | 三个文件必须同目录；路径不要有中文的话更保险（可整个 `obs-fx` 拷到 `E:\obs-fx`） |
| 圈的位置和真实鼠标偏移 | 看日志那行「映射区域」，不对就把「坐标区域」改成「自定义」手填该屏的左上角坐标和分辨率 |
| **独立层只识别主屏 / 位置对不上** | 「坐标区域」选 **自动**，并确认「联动缩放源」（或「接管用的采集源名」）填的是当前在录那块屏的采集源——脚本会读它捕获的显示器，区域和宽高都自动跟上；日志出现 `读不到联动源` 就是源名填错了/被删了/不是显示器采集。也可选「指定显示器」手动固定 |
| **换了块屏录制，高亮跑偏** | 采集源属性里换屏后，独立层约 2 秒自动重探测（日志有 `独立源宽高已跟随`）。若场景项把采集源缩放过，检查缩放后比例是否仍 1:1 |
| **画面上两个高亮圈 / 一大一小 / 颜色发灰** | 一个效果画了两遍。最常见：给「鼠标高亮层」挂了「鼠标高亮叠加」滤镜——进它的滤镜面板**删掉**（两种用法二选一，独立源身上不挂任何滤镜）。次常见：采集源上的滤镜和独立源同时都在画，二选一关掉。删完日志应只剩一套 `独立源自动匹配` |
| **开 obs-zoom-to-mouse 放大后高亮错位** | 独立层：在「联动缩放源」里选中被缩放的采集源（日志出现「找不到 zoom 裁剪滤镜」就是没选对/滤镜还没建）；滤镜版：确认「鼠标高亮叠加」排在裁剪滤镜**下方** |
| 完全不出效果 | 确认滤镜在采集源上且已启用；日志里要有「首帧渲染完成」 |
| **画面上两个光标** | 采集源的「捕获光标」没被关掉——烤进画面的系统光标和自绘光标分家了。确认「自绘接管」「自绘光标」都勾着，「接管用的采集源名」填成你的采集源（或「联动缩放源」已选）。想看准确原因就勾「输出日志」重载，日志里会写明是哪条路径没配上；同一原因 60 秒内只提示一次，不会刷屏 |
| 日志报「找不到 zoom 裁剪滤镜」 | 「联动缩放源」选的那台采集源上没有 obs-zoom-to-mouse 的裁剪滤镜（zoom 脚本没加载 / 源选错了 / 滤镜被删）。插件**不会**拿采集源上其它 Crop/Pad 滤镜顶替，先按未放大处理；zoom 脚本建好滤镜后约 2 秒自动接上 |
| **光标不见了** | 采集源的「捕获光标」被关了，但脚本没画出来。把「输出日志」打开重载，看有没有 `已抓到系统光标` / `自动读取系统光标失败`；失败就把「自动读取」关掉，用自带的 `cursor.png`。脚本每 2 秒会自己重试，能取到就自动切回真光标 |
| **换了光标主题，画面还是老光标** | 点「重新抓取光标」按钮强制重取。Windows 有时会把旧光标**回收成同一个句柄**再给新光标，脚本光比句柄看不出变化，所以留了这个手动开关 |
| **光标闪一下黑块 / 规律性闪黑** | v0.9.7 已修。原因：光标掩码是 **1bpp** 位图，脚本早先用 32bpp 去读它，读出来全 0 → 每个像素都算「不透明」→ 光标被画成一整块黑。现在按 1bpp 正确解析。若还出现，点「重新抓取光标」并重载脚本 |
| 光标的形状不对 / 位置偏了 | 「自动读取」关掉后用「光标图片」+「热点 X/Y」手调（热点 = 图片里那个尖/作用点相对左上角的像素位置） |
| 录制时鼠标不动 | 脚本只在画面渲染时更新坐标，源被隐藏/停用是正常的 |
| **一开 OBS 就弹「上次异常关闭 / 安全模式」窗口** | 上一次关闭时崩了。本版已修（不再跨帧持有采集源引用）；若仍出现，看 `%APPDATA%\obs-studio\crashes\` 最新文件确认 |
| **脚本日志自己弹出来 / 狂刷** | 只有**真致命错误**（effect / blank.png 加载失败 = 插件画不了）才会无条件弹日志窗；其余全是引导性提示，走 INFO 级，**默认关闭、永不弹窗**，只跟着「输出日志」开关走。所以取消勾选「输出日志」就彻底安静。另一个弹窗来源是 obs-zoom-to-mouse 的「启用调试日志」，在它的面板里取消勾选 |

## 六、文件

```
obs-fx/
  mouse-fx.lua     脚本主体（FFI 读鼠标 + 抓系统光标 + 滤镜/源注册 + 参数面板）
  mouse-fx.effect  着色器（画圈 / 波纹 / 拖影 / 光标图）
  blank.png        4×4 透明载体图，绘制用，别删
  cursor.png       光标图（32×32 中性箭头，自动读取失败时的兜底；可用 dev-archive/make_cursor_png.py 重新生成）
```

抓到的光标位图会临时写成 PNG 放到系统临时目录（`%TEMP%\mousefx_cur_*.png`），
载入显存后**立即删掉**，不会留垃圾。
